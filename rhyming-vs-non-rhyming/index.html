Rhyming vs Non-Rhyming World Models

A world model that recognizes structure against one that recognizes only words. Same models, same data, one question: which one does more work when agents share a world?

Same model, two deployments

The cleanest test of rhyming against non-rhyming keeps the world model fixed and changes only how agents share it. Four agents each see one CartPole dimension. In the non-rhyming deployment every agent keeps a private copy of the model and the group votes. In the rhyming deployment agents write into one shared world and a single model reads the merged state. Each model drives its own controller by rolling its learned dynamics four steps ahead. No hand-written balancing rule is used for any model arm. Random play scores 20.5.

The shared world predicts the next state 5.7× to 20× better for every model. It changes the outcome for one of three: the Dreamer-family arm falls from 199.5 to 139.3 when its agents are cut off from each other. The other two stay at 200 because the pole-angle agent alone carries enough signal for this task. We report that rather than hide it. A task where several agents hold different necessary facts is the next step.

Same structure, different words

The three compact arms (Dreamer-family RSSM, TD-MPC-lite, MuZero-lite) are small PyTorch models trained in seconds. They carry the same-model test above because their dynamics can be queried for any partial state. None of the seven arms has a share or merge operation, which is the job the rhyming shared world does.

Not run: V-JEPA 2-AC (about 1B parameters, not distributed as a standard checkpoint, beyond this machine's memory), Cosmos (GPU) and Genie (closed). DIAMOND and Oasis are GPU-class and were not attempted. Upstream arms were trained for minutes, so returns reflect short training. Each model is scored on its own task, so the returns are not a ranking.

Verdict

Rhyming and non-rhyming world models do different jobs. Open latent models own single-agent imagination and planning. A rhyming shared world owns share, merge and structure reuse, which is where multi-agent work happens. The two are complementary, and the measured differences above are specific to the second job.

What this does not show. On the protein task a plain structured blackboard also reached 100%, so the claim there is bytes, not accuracy. The shared-world accuracy gain comes from sharing, and a blackboard would match it. The rhyme layer's own contribution is the byte saving and structure reuse. Compact arms are small CPU implementations, not full checkpoints. Upstream arms were trained for minutes, so their numbers describe short training, not each model's ceiling. V-JEPA 2-AC, Cosmos and Genie are not run. Architectural and structured-state measurements, not production fleet benchmarks.
