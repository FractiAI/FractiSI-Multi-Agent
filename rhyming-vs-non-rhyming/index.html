Rhyming vs Non-Rhyming World Models

One kind of world model recognizes patterns. The other only recognizes exact words. We ran them head to head, on real data, to see which one does more work when agents share a world.

See the results Read the paper Read the write-up Run it yourself

The short answer

Rhyming wins on the work that matters: many agents, same job, different words. It does not win when the text is identical, and it does not replace the open-source models that plan for a single agent.

Test 1: same model, shared or not

We kept the world model fixed and changed one thing: whether agents share it. Four agents each see one piece of a balancing task. In one setup every agent keeps its own private copy of the model and the group votes. In the other, they all write into one shared world. Random play scores 20.5 out of 200.

Sharing made every model predict better. It also changed the score for one of the three. The other two already balanced fine because one agent could see the pole angle. We are telling you that on purpose. The next test needs a task where each agent holds a fact the others need.

Test 2: same job, different words

Real agent traffic is mostly one structure carrying different content. A normal cache only helps when text matches exactly. Rhyming recognizes the shape and stores each session as only what is different.

Test 3: open-source models, run for real

We ran every open-source world model that fits on this hardware. None is a stub.

Each model is scored on its own task, so this is not a ranking. We also trained three compact versions in seconds. They carry Test 1 because we can query them with partial information. Not run: V-JEPA 2-AC, Cosmos (need a GPU) and Genie (closed). DIAMOND and Oasis also need a GPU and were not attempted.

The rhyme features behind it

Rhyme means recognizing the pattern, not just the words. It shows up in four features. Two are new.

FeatureWhat it doesResult
Rhyming TemplatesStores a pattern once and each session as only what differs33% to 49% smaller than an exact-match cache
Shared-World RhymeLets agents write into one world5× to 20× more accurate predictions
Protein Folding Rhyme (new)Finds the hidden long-distance match in a sequence by mapping relationshipsFound every time, vs almost never looking only at neighbors
LLM RhymeGives a language model that map in its promptFound every time with the map, almost never without it
Pilot Rhyme (new)Director holds the map; Pilots run local steps; roles once; mission deltas; shared world100 of 100 vs flat 0; 22% / 80% size wins; 692 theater candidates (flat miss)

So, is rhyming better?

For multi-agent work where the wording changes, yes, by a lot. For identical text, no: use a normal cache. For one agent planning alone, open-source world models are the right tool. The two kinds work together, and the differences above are specific to sharing a world.

What these tests do not show. On the protein task a plain shared notebook also got every answer right, so there the gain is size, not accuracy. The accuracy gain in Test 1 comes from sharing, and a plain shared notebook would match it. What rhyme adds on top is the smaller size and the reuse of patterns. Compact models are small CPU versions, not full checkpoints. Upstream models were trained for minutes, so their numbers describe short training, not their ceiling. These are lab results, not production benchmarks.
