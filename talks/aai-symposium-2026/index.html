The multi-agent problem and opportunity

Opportunity

  • Specialized agent collectives
  • Research · plan · code · review · safety
  • More perspectives on one hard problem

Problem

  • Share, coordinate, compose without chaos
  • Same world reprinted per agent
  • Missed discoveries · slow convergence

Both sides together — that is what FractiSI addresses.

Step 1 · Problem & opportunity

One world, many copies

Problem

Every agent reprints overlapping copies of the same world.

Opportunity

One shared world; agents keep only what differs.

FractiSI: shared world once · per-agent deltas.

Step 2 · Problem & opportunity

Gzip is not an architecture

Problem

Compression shrinks copies — it does not remove them.

Opportunity

Share the world first; compression becomes optional polish.

FractiSI: stop paying N copies before you compress.

IDE now node scripts/tiny.mjs testdrive 2

Show gzip on both arms; shared still ahead. Cross-copy tax is structural.

Step 3 · Problem & opportunity

When words differ, exact cache fails

Problem

Exact-text / prefix cache only helps when the words match.

Opportunity

Same shape, different wording can still share structure.

FractiSI: rhyming templates · Tiny Footprint / Tiny Gateway.

IDE now node scripts/tiny.mjs testdrive 3

Forty same-shape different-words sessions. Rhyme beats exact cache.

Step 4 · Problem & opportunity

Discovery flat skim misses

Problem

Fixed-budget flat retrieval buries multi-hop chains in noise.

Opportunity

Relationship-guided recovery finds what flat skim never assembles.

FractiSI lab: 100 / 100 vs flat 0 / 100 (Expedition 002 · E2).

Step 5 · Problem & opportunity

Convergence takes too many rounds

Problem

Too many ops and propagation rounds before a composed answer.

Opportunity

Fewer rounds and ops on the same constrained path.

FractiSI lab: −50% rounds · −85% ops (architectural convergence).

Problem

Opportunity
